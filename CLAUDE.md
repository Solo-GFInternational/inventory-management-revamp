# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Stack

Laravel 13 (PHP ^8.3) on the Laravel 11+ skeleton (`bootstrap/app.php` holds middleware aliases and routing; there are no HTTP/Console kernels). Server-rendered Blade with no JS framework, Tailwind v4 via `@tailwindcss/vite`, SweetAlert2 served locally from `public/vendor/sweetalert2`. PDF export via `barryvdh/laravel-dompdf`; audit trail via `spatie/laravel-activitylog`. Upgraded from Laravel 9 (Breeze) on 2026-10-28; the auth controllers are the old Breeze ones, adapted.

## Commands

```bash
composer install && npm install
cp .env.example .env && php artisan key:generate
php artisan migrate --seed   # seeds demo accounts (see below)

npm run build              # views are served from public/build: re-run after any class change
php artisan serve          # app at http://localhost:8000 (use --port if 8000 is taken)

php artisan test                                   # all tests
php artisan test --filter=InventoryStockTest       # one class
php artisan test --filter=test_admin_create_deducts_stock_immediately  # one method
./vendor/bin/pint          # code style
```

- **Corporate proxy:** HTTPS is intercepted with a self-signed root, so Composer (curl error 60) and npm fail. Export the Windows trusted roots to a PEM file and set `COMPOSER_CAFILE` / `NODE_EXTRA_CA_CERTS` to it; don't disable TLS verification. `npm run build` also downloads Instrument Sans (`bunny()` in `vite.config.js`, self-hosted, emitted via `@fonts`).
- **Demo logins** (`Database\Seeders\DemoSeeder`, idempotent): `admin@demo.test` / `password` (admin), `user@demo.test` / `password` (user). Self-registration is removed; admins create users under Settings.
- **Tests** use `RefreshDatabase` against `inventory_management_revamp_test` (`DB_DATABASE` in `phpunit.xml`), never the dev database. A real env var overrides it, e.g. `DB_DATABASE=other_test_db php artisan test`, which is how parallel runs avoid wiping each other.

## Domain and architecture

IT equipment issue tracking: staff record items handed out (`inventories`) against per-item shelf counts (`stocks`). Controllers in `app/Http/Controllers`; stock arithmetic lives in `App\Services\StockLedger`.

- **Roles**: plain `users.role` string (`admin` | `user`); `User::isAdmin()` / `isUser()`. Middleware aliases in `bootstrap/app.php`: `role:<name>` (`RoleMiddleware`) and `admin`. `EnsureUserIsActive` (web group) signs out deactivated accounts; `LoginRequest` refuses them.
- **Stock invariant** (relied on by Stock, Dashboard and `StockLedger`): `stocks.qty` is what is on the shelf now, and stock is deducted for exactly the inventory rows that are active AND `status = 'approved'` AND `condition = 'new'` AND not returned (`returned_at IS NULL`). Given out = SUM(qty) of those rows (grouped by `stock_id`); Total = in stock + given out. `StockLedger::save()` moves the difference between a row's before/after holding inside a transaction with `lockForUpdate`, and throws a `ValidationException` on `qty` rather than going negative.
- **Create is multi-record, edit is single** (`InventoryController::store`): the create modal takes date, condition, item and site once, plus `people[N][taken_by|department_id|serial_number]` rows ("+ Add person", `_person.blade.php` + a `<template>` block in app.js, capped at `MAX_PEOPLE` = 50). Each person becomes one record with `qty = 1`, all in one transaction through `StockLedger::save()` (all or nothing; errors on the `people` key). `qty` is no longer editable; the column stays because imported legacy rows can hold more than 1.
- **Barcodes** (`App\Services\BarcodeLabel`, picqer Code 128 drawn with GD): `Inventory::booted()` assigns `barcode` = `INV` + 6-digit id on `created` (direct query update, no audit entry; `barcode` isn't fillable) and writes `barcodes/{barcode}.jpg` on the `local` disk after commit. `BarcodeLabel::ensure()` redraws a missing file on download/view; `php artisan inventory:barcodes` (routes/console.php) backfills. `ux_inventories_barcode` is unique over all rows (filtered `IS NOT NULL`, not on `active_yn`) so a label never moves to another record. `TestCase` fakes the `local` disk.
- **Scanner** (`ScannerController`, `resources/js/scanner.js`): decoding happens in the browser with `@zxing/browser` (Code 128 only, rear camera, 720p) because no PHP package can reach the camera and `BarcodeDetector` isn't on Windows Chrome/Edge. A read stops the camera, shows the processing alert and navigates to `scanner.lookup?code=`, which matches `barcode` (trimmed, upper-cased, deactivated rows included) and redirects to `inventory.show`, or back with an `error` flash. Camera access needs HTTPS or localhost; otherwise the page falls back to manual entry. scanner.js is its own Vite input, pushed via `@push('scripts')` (`@stack('scripts')` in `layouts.app`).
- **Handover** (`HandoverController`, `inventory/_handover.blade.php`): a record is the physical item, so a handover keeps the same row and barcode. *Return to stock* (any user; active, approved, not returned) sets `returned_at`/`returned_by` through the ledger (a new unit goes back on the shelf). *Assign to new person* (only once returned, not pending) sets date/taken_by/department/site and clears the returned fields: admin → stays approved and re-deducts; user → pending `edit` approval with the diff in `change_log` (shared diff/merge in `App\Support\InventoryChangeLog`). Both write a timeline entry in the same transaction.
- **Timeline** (`inventory.inventory_updates`, `InventoryUpdate`, `InventoryUpdateController`, `inventory/_timeline.blade.php` on the show page): `kind` note | returned | assigned. Any user can add a note to an active record (validation uses the `timeline` error bag, shown inline); the author or an admin can remove (deactivate) a note; system entries can't be removed. The feed ends with a synthesized "Record created" entry from the row itself.
- **Approval workflow** (`InventoryController`): admin creates are approved immediately (stock deducted); user creates are `pending` / `approval_type = 'new'`. A non-admin edit that changes something goes back to pending (`approval_type = 'edit'`, diff merged into `change_log` — computed on ids but stored as names under `item`/`department`/`site`, so the approvals page shows what the user saw — `edited_by` set) and returns its stock; approval re-checks stock and deducts. Approvals are logged with `activity('inventory')->event('approved')`.
- **Item / department / site**: inventory rows hold foreign keys, not text: `stock_id` (→ `inventory.stocks`, the item master; name in `stocks.item`), `department_id` and `site_id` (→ `ref.types`). The Item dropdown lists active stocks; Department and Site come from `Type::options()`, which keeps a record's current value listed even if it has since been deactivated.
- **Types** (Settings > Types, `TypeController`, `App\Models\Type`, modelled on tender-management's `ref.types`): managed dropdown lists, one row per option grouped by `type_group` (`Type::GROUPS`: department, site). Only lists people maintain belong here; values that drive behaviour (role, condition, status, approval_type) stay as check-constrained columns. Never deleted, only deactivated. `TypeSeeder` holds the initial lists and is idempotent.
- **Users** (`UserController`, ported from tender-management): the create modal has no password field. `store()` generates one (`App\Support\TemporaryPassword`) and emails it with `App\Mail\UserAccountCredentials` (queued, `ShouldBeEncrypted`; sent in-request while `QUEUE_CONNECTION=sync`; `MAIL_MAILER=log` locally writes it to `storage/logs/laravel.log`). Reusing a deactivated account's email reactivates it with a new emailed password; the Reactivate button keeps the old one. If sending throws, the account is kept, the error is reported, and an `error` flash tells the admin. The password is never shown, flashed or logged. The edit modal keeps an optional password (no email), as in tender. Emails use the published `resources/views/vendor/mail` layout (from tender); `App\Listeners\EmbedGfLogoInEmails` embeds the logo by Content-ID (`App\Support\EmailBranding`).
- **No hard deletes**: "delete" on inventory and users sets `active_yn = false`; lists, totals and the PDF exclude inactive rows. `DELETE /profile` returns 403 (accounts are admin-managed). Deactivating an approved new inventory row puts its qty back into stock.
- **Audit trail** (Settings > Audit Trail, `AuditTrailController`, `App\Support\AuditTrail`): ported from the sibling site-visit project. `HasStandardColumns` adds spatie's `LogsActivity` to every business model (dirty columns only, old → new; passwords, `change_log` and bookkeeping columns excluded; `active_yn` flips logged as deactivated/reactivated). `RecordSignIns` listener logs sign in/out and failed sign-ins; `RecordPageView` middleware logs signed-in HTML GETs. `App\Support\AuditTrailEntry` (the configured activity model) stamps the request IP on every entry. Logging failures are reported, never thrown. The log lives in `logs.activity_log` (`config/activitylog.php`).

## Routes (`routes/web.php`)

`auth`: dashboard, profile, inventory index/store/update/show + PDF, `inventory.barcode` (JPEG download; `?inline=1` serves it inline for `<img>`), stock index/store, `scanner.index` / `scanner.lookup`, `inventory.return` / `inventory.assign` (PATCH), `inventory.updates.store` / `.destroy` (scoped binding). `/inventory/{inventory}` routes use `whereNumber` so `/inventory/pending` and `/inventory/download-pdf` aren't captured. `auth` + `role:admin`: inventory pending/approve (POST or PATCH)/destroy (deactivate), stock update (correct a count), and Settings at `/settings/users` (`users.*`, incl. `users.reactivate`), `/settings/audit-trail` (`audit.index`) and `/settings/types` (`types.*`, incl. `types.reactivate`). Create/edit happen in modals; there are no create/edit page routes. `inventory.show` is a view-only details page (where a scan lands).

## UI conventions (copied from tender-management, which mirrors site-visit)

Build pages from the shared pieces; don't restyle by hand.
- **Layouts**: `layouts.app` (navy top bar: Goodman Fielder logo `public/images/goodman-fielder-logo.png` left, system name centre, user menu right, icon nav row; admins see Approvals with a pending badge and Settings) and `layouts.auth` (sections `title`, `form-action`, `heading`, `subheading`, `content`, `form-attributes`, `after-form`). Pages use `@extends` + `@section('content')`.
- **Components** (`resources/views/components`): `x-page-header`, `x-card`, `x-button`, `x-icon-button` (icon-only row actions; `disabled-reason`), `x-icon` (Heroicons outline from `resources/svg/heroicons`), `x-modal` (native `<dialog>`), `x-form-errors`, `x-badge`, `x-settings-tabs`, `x-nav-link`.
- **CSS** (`resources/css/app.css`): `primary-*` teal, `gray-*`, `danger-*`, `brand-navy`; `.gf-label`, `.gf-input`, `.gf-hint`, `.gf-readonly-field`, `.gf-table`. Every `<select>` is `class="gf-input select-arrow"` (no forms plugin).
- **JS** (`resources/js/app.js`): `data-modal-open="{id}"` / `data-modal-close`; `<form data-confirm=...>` SweetAlert confirm (closes an open modal while asking, reopens it on Cancel); `<form data-processing="Saving…" data-processing-text=...>` non-dismissable spinner, on every form that changes data (create/edit/approve/deactivate/reactivate, stock, profile, password) but never on GET filters, the PDF download (a download never leaves the page, so it would spin forever) or sign in/out; `ProcessingAlertTest` enforces this, so give new POST forms one. It shows after a confirm, closes the modal so it's visible, and is cleared by the next page load or a Back-button `pageshow`. Flash `->with('status')` (success) / `->with('error')` / validation errors as SweetAlert. Modal forms carry a hidden `_modal` value and `:open="old('_modal') === '...'"` so failed validation reopens the right modal.

## Database

- **SQL Server only.** The legacy system ran on MariaDB (a phpMyAdmin dump `inventory_system.sql` may sit in the repo root; `*.sql` is gitignored because it holds staff data and password hashes); production moves to SQL Server, with the old data imported once at go-live. Local dev: `localhost\SQLDEV`, Windows auth (`DB_CONNECTION=sqlsrv`, blank `DB_PORT`/`DB_USERNAME`/`DB_PASSWORD`, `DB_TRUST_SERVER_CERTIFICATE=true`), database `inventory_management_revamp`. The separate `inventory_management` database on SQLDEV belongs to another project.
- **Schemas** (created by the first migration): `security` (users, password_reset_tokens), `inventory` (stocks, inventories, inventory_updates, assets), `ref` (types), `logs` (activity_log). Framework plumbing (migrations, cache, jobs, sessions, failed_jobs) stays in `dbo`. Models set `$table = 'schema.table'`. The migrations are a clean baseline (2026-10-28) replacing the Laravel 9-era history.
- **Validation gotcha:** a raw `'schema.table'` string in `Rule::unique()` / `Rule::exists()` / `'unique:...'` is read as a *connection* name. Pass the model class: `Rule::unique(User::class, 'email')`.
- **Constraints** are named `ux_/ix_/fk_/ck_<table>_<cols>`; every FK is `NO ACTION` (SQL Server rejects multiple cascade paths). Unique indexes on deactivatable columns are filtered `WHERE active_yn = 1` (`ux_users_email`, `ux_stocks_item`, `ux_types_type_group_type_name`, `ux_assets_asset_tag`). Fixed value lists are CHECK constraints (`ck_users_role`, `ck_inventories_condition/status/approval_type`, `ck_inventories_qty >= 1`, `ck_stocks_qty >= 0`). `App\Support\Database\StandardColumns` has the migration helpers for all of this.
- Business tables (`users`, `stocks`, `inventories`, `inventory_updates`, `assets`, `types`) have `active_yn`, `created_by`, `created_at`, `updated_by`, `updated_at`, with `created_by`/`updated_by` as FKs to `security.users` — add them with `StandardColumns::add()` in migrations and `App\Models\Concerns\HasStandardColumns` on the model (fills the user columns, `active()` scope, audit logging). `active_yn` isn't mass-assignable: set it with property assignment or `forceFill`. `logs.activity_log` is append-only (exempt) but `causer_id` is a real FK to users.
- **Blade gotcha:** don't mix the inline `@php(...)` form and a `@php ... @endphp` block in one template; Blade pairs them wrongly and the compiled view fails to parse.
- Timestamps are stored in UTC (`config/app.php`).
- pdo_sqlsrv returns integer columns as strings; compare IDs with `==` / `assertEquals`, not strict equality.
